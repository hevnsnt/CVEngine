Sentinels

A Sentinel is a scanner you run on your own network: it registers itself, pulls nmap, naabu and nuclei work off this project's queue, runs it and reports typed results back. This phase covers nmap, naabu and the nuclei passes; a scan with no live Sentinel runs those locally exactly as before.

Registered Sentinels

    No Sentinel has registered yet. Generate an enrollment secret for a project and give it to a Sentinel's setup.

    Provision a Sentinel

    Needs the admin role in the project (or App Admin). Clicking Provision generates a one-time enrollment secret, single-use and expiring in 30 minutes, and packages it into one opaque blob. Clone this repository onto the machine that will scan, paste the blob into CVENGINE_SENTINEL_BLOB in sentinel/.env, and run docker compose -f sentinel/docker-compose.yml up -d; see sentinel/README.md.

    What a Sentinel needs

    The blob is nothing new: standard base64 of the same JSON sentinels/enroll already returns ({enrollment_token, server_url, expires_at, project}), so the Sentinel client can decode it in a few lines with no shared library. It calls POST /api/v1/sentinels/bootstrap with the decoded enrollment_token, stores the token it gets back, then loops sentinel/heartbeat and sentinel/tasks/next, accept, result. The OpenAPI spec is at /api/v1/openapi.json.
