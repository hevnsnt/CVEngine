Sentinels

A Sentinel is a scanner you run on any machine: deploy one or a hundred to spread this project's scanning. It registers itself, pulls scan work off this project's queue (nmap, naabu, the nuclei passes, TLS audits, UDP sweeps, WPScan, OpenVAS and, on an internal network, host discovery), runs it and reports typed results back. A scan with no live Sentinel runs the external stages locally exactly as before; work on an internal network only ever runs on a Sentinel inside it.

Provision a Sentinel

A Sentinel can be scoped to one project, one organization (every project of it, present and future) or, for an App Admin, the whole instance (every organization and project). Whichever scope, Provision gives you one command to paste on the machine that will scan, and a ready-made prompt to hand an AI agent instead. Both carry a single-use secret that expires in 30 minutes. The machine needs Docker with Compose, git and outbound HTTPS to this server. The client is hevnsnt/cvengine-sentinel.

What a Sentinel needs

The blob is nothing new: standard base64 of the same JSON projects/{slug}/sentinels/enroll, orgs/{slug}/sentinels/enroll or sentinels/enroll already returns ({enrollment_token, server_url, expires_at, scope}, plus project or org where scope is not instance-wide), so the Sentinel client can decode it in a few lines with no shared library. It calls POST /api/v1/sentinels/bootstrap with the decoded enrollment_token, stores the token it gets back, then loops sentinel/heartbeat and sentinel/tasks/next, accept, result. The OpenAPI spec is at /api/v1/openapi.json.
