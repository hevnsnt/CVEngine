What runs where

Every scan runs on a Sentinel, a small scanner you run on any machine. The server queues the work, keeps the data and shows the results.

Server

Runs on the machine you install CVEngine on

  • The web app, API and PDF reports
  • CVE catalog sync and matching
  • PostgreSQL, Redis, the Celery queue and the nginx proxy
  • The AI reviewer, idle until you set up a provider
  • The built-in scanner, a last resort that takes work only when no Sentinel can

Sentinel

One machine or a hundred, including inside networks the server cannot reach

  • Port and service scans with naabu and nmap
  • nuclei, the testssl.sh TLS audit, WPScan, wafw00f and bbot discovery
  • Kingfisher secret detection and the sshamble SSH host key check
  • Headless Chromium screenshots
  • Web, DNS and route probes, hygiene checks and the UDP sweep

Open source at github.com/hevnsnt/cvengine-sentinel

OpenVAS add-on Optional

Greenbone Community Edition, in separate containers a Sentinel runs

  • Off until you choose the Full size when you add a Sentinel
  • Checks for known weaknesses with a large, regularly updated set of tests
Details

For engineers and auditors: it is switched on with COMPOSE_PROFILES=openvas on a Sentinel.

The parts: gvmd, ospd-openvas, openvas-scanner, pg-gvm, Redis and the Greenbone feed data. CVEngine drives it over GMP with python-gvm.
