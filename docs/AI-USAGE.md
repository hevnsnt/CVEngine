# AI model usage

Once an AI model is connected, the account menu shows **AI Model Usage** (superusers), refreshed every 15 seconds. It records every completion cvENGINE requests from Anthropic, OpenAI, OpenRouter, Ollama, vLLM, or LM Studio:

- calls per day and per pipeline stage, including failed ones with a safe error category (choose 24 hours, 7 days, or 30 days). The stages are `finding_triage`, `finding_triage_repair` (the second call after a rejected triage reply, so one triage can be two rows), `cve_confirmation`, `validation_plan`, `local_check_suggestion`, `cve_detection`, `nuclei_tag_selection`, `nuclei_targeting`, `template_generation`, `assessment_review`, `performance_review` (older rows: the three-hour capacity check no longer asks the model), `autotune_advisor` (the auto-tuner's advisor, capped by `CVENGINE_AUTOTUNE_AI_MAX_PER_DAY`), `rdp_screenshot`, `report_writing`, and `connection_test`; a call made outside any named stage is recorded as `unspecified`. The page shows the top 30 stages, the top 100 models, and the last 50 calls;
- the model that answered, input, output, and cache tokens as the provider reports them, and latency;
- connection health: a recent successful call, a recent error, an old verification, or not yet verified. Changing the provider, model, server, or key resets it.

## Cost estimates

An App Admin enters the price for each exact provider and model ID: USD per million input and output tokens, cache rates, an HTTPS source URL, and the date checked. cvENGINE multiplies it by the tokens used to show a **known estimated cost**. Calls without token counts, without a matching price, or with cached tokens but no cache rate count separately as **unknown cost**, so the estimate never pretends to be complete. It is an estimate, not an invoice, and local models still cost the hardware they run on.

## Spend levers

**Cost by stage and day.** `GET /cve/api/settings/ai/usage` returns `cost_by_stage_day`: for every day, stage and model, the calls, failed calls, input, output, cache-read and cache-write tokens, the cache-read share (cache read over every prompt token) and the list-price dollars. The rates are in `web/cveFeed/ai_list_prices.json` (edit the file to change one); a price entered on this page for the exact model wins. A cache write is priced at the stage's own lifetime, because the ledger keeps one write count. The Message Batches discount is not applied. Calls without token counts are counted in `unpriced_calls` and left out of the dollars.

**Prompt caching (Anthropic only).** Each stage's system prompt carries one cache breakpoint. A cached read costs 10% of the input price (5% on Sonnet 5.5); a write costs 1.25 times (5 minute lifetime) or 2 times (1 hour). The shortest prompt Anthropic caches is 512 tokens for Haiku 5.5 and Sonnet 5.5, so `assessment_review` (about 140 tokens), `autotune_advisor`, `template_generation`, `nuclei_tag_selection` and `cve_confirmation` are too short to benefit and are sent unmarked. Cached today: `cve_detection` (about 2,000 tokens, 1 hour: the task runs every 30 minutes, so each run reads the previous run's write), `finding_triage` and `finding_triage_repair` (about 1,150, 5 minutes), `validation_plan` (about 640, 5 minutes), and `local_check_suggestion` (about 500, borderline). `nuclei_targeting` is left uncached: its system prompt carries the tag list offered for that scan, which differs between scans, and a write nobody reads costs 25% more. Grouping calls of one stage in time is what keeps a 5 minute entry alive: a read renews it, so calls less than 5 minutes apart never pay a second write, and calls sent at the same moment each pay one (an entry can be read only after the request that writes it has started to answer, so `cve_detection` sends the first record of a run alone). The ledger's `cache_read_tokens` and `cache_write_tokens` show it working.

**Message Batches (not built).** Half price on input and output, results within 24 hours (most in an hour), stacks with caching (use the 1 hour lifetime). Stages that tolerate hours of delay: `cve_detection` from the 30 minute authoring task (the backlog; not `revise_with_guidance`, which an administrator waits for), `template_generation` for the candidate pass, and `autotune_advisor` (a handful of calls a day). Not eligible: `finding_triage`, `validation_plan`, `nuclei_targeting`, `local_check_suggestion` and `assessment_review` (a scan or a person waits for them). A change would touch `AnthropicProvider` (a submit and a collect call), a table for the pending batch ids and the CVE each request belongs to, a collector task that writes the answers through the same validation (`detection.parse_ai_strategy`, `_apply_answer`) and one `AIUsage` row per result (at the batch price), and the daily budget (`ai_budget_left` counts at submit time). It needs a worker restart to deploy and a decision on the budget accounting, so it is not in this change.

## Privacy

Only App Admins can see the page, call its API (`GET /cve/api/settings/ai/usage`), or change prices. The ledger stores no API keys, prompts, responses, targets, or provider error bodies, and the settings API reports whether a key is set, never its value. History starts when the feature is installed, and rows older than 400 days (`CVENGINE_AI_USAGE_RETENTION_DAYS`) are written each Sunday to a file only a superuser can download, then deleted from the database. Archives are kept 365 days (`CVENGINE_LOG_ARCHIVE_DAYS`).
