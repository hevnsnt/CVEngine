# CVEngine 1.1 — Host detail & fingerprinting (plan)

Goal: Shodan/BinaryEdge-level host records. When a host and its ports are
alive, do everything reasonable to identify what is listening and record the
metadata, so a search like `php` reliably finds every host running it.

This is a plan for review. Nothing here is built yet.

## Where we are today (from a full read of the pipeline)

- **nmap** runs `-sV --version-intensity 5 -O` on the top 1000 ports plus ~25
  high-risk extras (`cveFeed/nmap_scan.py`). It keeps product, version, CPE,
  extrainfo and an OS guess **per IP** (`persist_inventory`).
- **No NSE scripts** run in the real pipeline (`--script` only exists in the
  legacy reNgine engine path), and **no banners are stored** — `Port.banner`
  exists but nothing ever writes it.
- **Web tech** comes from three places: bbot's httpx (Server header, title,
  status), the route check's `fingerprint.from_response` (Server, X-Powered-By,
  generator meta, body markers), and nuclei's `tech` templates. These become
  `Technology` rows (name only — no version, category or source column).
- **DB exposure** check connects read-only to Redis/Memcached/Postgres/Elastic/
  CouchDB and flags no-auth access, but does **not** record a version string.
- **Search**: a bare word matches host name, title, technology names, IP,
  OS guess, vuln name, CVE id, and (open ports only) port product/service/
  version/cpe. It does **not** search the webserver field, banners, headers or
  `service_extra`. `tech:php` matches technology names only.
- **Display**: `showHost` renders ~16 sections. The API already sends
  `technology_details` (name/version/category/source), host-level `http`
  (webserver, powered_by, …) and `hosting`, but the UI never renders them.

## The plan, in phases (each its own PR into `develop`)

### Phase A — collect more, safely (no new auth, no exploit)
1. **nmap banners + safe NSE.** Add `--script=banner` and a small, vetted
   safe-category set (`ssh2-enum-algos`, `ssl-cert`, `http-headers`,
   `ftp-anon` in report-only mode, `rdp-ntlm-info`, `smb-os-discovery`,
   `ssh-hostkey`) to the `-sV` pass, parse NSE `<script>` output in
   `nmap_service.py`, and finally write `Port.banner` and structured
   per-port `extra`.
2. **Service version → host OS.** Pull OS/version hints out of banners
   (OpenSSH portinfo, `rdp-ntlm-info` product/build, `smb-os-discovery`) and
   store them on the port and IP.
3. **DB version probes.** Extend `db_exposure` to record the server version it
   already reads (Redis `INFO server`, Postgres `server_version`, Elastic `/`,
   CouchDB `/`, MySQL/MSSQL handshake) as port product/version — read-only,
   no data access.
4. **Web spider & deeper tech.** Walk a bounded set of same-host pages
   (the existing route set + links found, capped) and run the fuller
   fingerprint matchers (framework/language markers, favicon hash, JS bundle
   names like React/Next/Vue, cookie names) — all GET, same-host only, under
   the existing probe budget.

### Phase B — model & search (make it findable)
5. **Technology gets version + category + source** columns; keep the current
   `name` working. `_host` already emits `technology_details`; back it with
   real columns.
6. **Search over everything we now store**: webserver, banners, `service_extra`,
   per-port `extra`, headers. `php` finds a host whether php shows up in a
   header, a banner, a cookie or a technology row.

### Phase C — display (the Shodan-style record)
7. **Rebuilt host page**: a structured record with OS, hosting/ASN, a per-port
   card (banner, product/version, CPE, TLS cert, HTTP headers), technologies
   with versions and categories, CVEs per port, and the raw banner shown the
   way Shodan shows it. Render the `technology_details`/`http`/`hosting` the API
   already sends but the UI drops today. (Design-system review first.)

## Decisions (made 2026-10-25)

This is the operator scanning their own authorized attack surface, so these
are enabled:

- **Anonymous FTP**: yes — attempt anonymous login, record banner, whether anon
  is allowed, and a top-level listing as evidence; flag a finding when open.
- **RDP**: `rdp-ntlm-info` always, **plus a screenshot of the RDP login and
  identifying the logged-in user on every scan where 3389 is open.**
- **SMB/NetBIOS**: yes — `smb-os-discovery` and `nbstat` for OS/hostname/domain.
- **Scan intensity**: deep always — raise `--version-intensity` and add the
  vetted NSE set on every scan (not gated behind a manual action).

Note: these run only against hosts already in scope for the project (the same
scannable-host gate the rest of the pipeline uses); nothing here widens scope.
